# Prompt Manager

Десктопный менеджер промтов: один промт — несколько вариантов, вложенные папки,
теги, картинки 500×500, полнотекстовый поиск и двусторонняя синхронизация с
WebDAV. Хранение — Markdown с YAML frontmatter плюс JSON-индекс, без SQL.

Стек: Python 3.11+, [pywebview](https://pywebview.flowrl.com/) (окно и мост
JS↔Python), Pillow, PyYAML, python-dotenv, requests. Упаковка — PyInstaller.

## Возможности

- CRUD промтов и вариантов; у промта всегда есть хотя бы один вариант.
- Вложенные папки (до 6 уровней) и сворачиваемый сайдбар с деревом и счётчиками.
- Теги, облако тегов с частотой, фильтр по нескольким тегам одновременно.
- Полнотекстовый поиск по заголовку, тегам, описаниям и тексту `.md`; сниппеты
  с подсветкой совпадений.
- Сортировка: дата изменения, дата создания, заголовок (в обе стороны).
- Картинка варианта: любой читаемый Pillow формат → PNG 500×500 с подложкой
  `#2D2D2D`, с сохранением пропорций.
- Удаление — только в корзину `.trash/` с отметкой времени.
- WebDAV-синхронизация с разрешением конфликтов и семантическим слиянием индекса.

## Установка

Нужен Python 3.11+. На Windows требуется WebView2 Runtime — в Windows 10/11 он
уже установлен; если нет, скачайте с сайта Microsoft.

```bash
python -m venv .venv
# Windows (PowerShell):
.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

python -m pip install -r requirements.txt
```

Для тестов и сборки: `python -m pip install -r requirements-dev.txt`.

## Запуск

```bash
python main.py
```

Демо-данные (три промта в двух ветках папок, четыре варианта, одна картинка):

```bash
python tools/seed_demo.py
python main.py
```

Отладка: `PROMPTMANAGER_DEBUG=1` включает консоль разработчика WebView2 и
подробные логи. Логи пишутся в `data/app.log`, исправления индекса — в
`data/repair.log`.

## Интерфейс

- **Сайдбар.** Сворачивается кнопкой `☰` в шапке, кнопкой `«` или `Ctrl+B`;
  состояние, раскрытые папки и выбранная папка запоминаются между запусками.
- **Папки.** Иерархия задаётся полем «Папка» в редакторе промта (`Работа/Клиенты`).
  Клик по папке фильтрует список вместе с подпапками. Кнопка `⋯` на папке —
  переименование (можно переместить ветку) и «Убрать папку»: промты поднимаются
  на уровень выше, ничего не удаляется. Пустых папок не бывает.
- **Поиск.** Поле в сайдбаре, `Ctrl+F`. Запрос режется на слова, каждое слово
  должно найтись в промте (AND). Ищется в заголовке, тегах, описаниях и телах
  `.md`; найденный фрагмент показывается сниппетом с подсветкой.
- **Теги.** Облако внизу сайдбара, размер шрифта зависит от частоты. Клик
  включает фильтр, несколько тегов складываются по «И» (промт должен иметь все).
- **Сортировка.** В шапке списка: новые/старые сначала, заголовок А→Я и Я→А,
  дата создания. Выбор запоминается.
- **Промты.** «+ Промт» (`Ctrl+N`), «Изменить» (карандаш), «+ Вариант» (плюс),
  «Удалить» (корзина). Действия — иконки с подсказками.
- **Варианты.** Карандаш — редактор текста, корзина — в `.trash/`. Удалить
  единственный вариант нельзя: удаляйте промт целиком.
- **Картинки.** Иконка изображения в строке варианта: прикрепить/заменить/удалить.
  Миниатюра открывает предпросмотр. Исходный файл не изменяется, PNG хранится
  рядом с `.md` варианта.
- **Обновить** (`F5`) перечитывает `index.json` с диска — после ручной правки.
  `Esc` закрывает диалоги и меню, `Ctrl+B` — панель.

## WebDAV-синхронизация

Креды читаются только из `.env` (в git не попадает) или переменных окружения:

```bash
cp .env.example .env
# WEBDAV_URL=https://dav.example.com/path/to/prompts
# WEBDAV_USERNAME=user
# WEBDAV_PASSWORD=secret
```

`WEBDAV_URL` указывает прямо на папку-двойник `prompts/`; если её нет, приложение
попробует создать её через MKCOL. Кнопка с облаком — синхронизация, кнопка с
вилкой — проверка подключения.

Серверная часть не умеет хранить копии? Ничего страшного: при удалении файла на
сервере синк не удаляет его безвозвратно — перемещает в `_trash/<timestamp>/`
внутри WebDAV-каталога.

### Как разрешаются конфликты

Сравниваются три состояния: локальный файл, файл на сервере и база
`data/sync_state.json` (что было синхронизировано в прошлый раз).

| Локально | На сервере | Действие |
|---|---|---|
| изменён | без изменений | PUT с `If-Match` (ETag из базы) |
| без изменений | изменён | скачать и атомарно заменить локальный |
| изменён | изменён | **конфликт** |
| удалён | без изменений | серверный файл → `_trash/<ts>/` |
| без изменений | удалён | локальный файл → `.trash/remote/<ts>/` |
| удалён | изменён | скачать заново (правка важнее удаления) |
| изменён | удалён | загрузить заново |

При конфликте локальная версия остаётся на месте и уходит на сервер, а
удалённая сохраняется как
`.conflicts/<timestamp>/<папка>/<имя>.conflict-<timestamp>.<ext>`.
Ничего не теряется и не перезаписывается молча; копии лежат вне `prompts/`,
чтобы не превращаться в варианты промтов.

`index.json` — особый случай: при одновременном изменении с двух сторон он
сливается семантически (union по `id`, побеждает запись с более новым
`updated`, варианты объединяются по `id`). Если JSON с одной стороны битый —
включается то же правило конфликт-копии.

### Локальный WebDAV для проверки

```bash
# терминал 1
python tools/dav_server.py --root .davserver --port 8099

# .env
WEBDAV_URL=http://127.0.0.1:8099/
WEBDAV_USERNAME=user
WEBDAV_PASSWORD=secret

# терминал 2
python main.py
```

## Данные

| Режим | Каталог |
|---|---|
| из исходников | корень проекта |
| собранный `.exe` | рядом с исполняемым файлом, если каталог доступен на запись, иначе `%APPDATA%\PromptManager` |
| macOS / Linux, fallback | `~/Library/Application Support/PromptManager`, `~/.local/share/PromptManager` |
| явное переопределение | переменная окружения `PROMPTMANAGER_DATA` |

```
prompts/            # синхронизируется с WebDAV, структура строго по ТЗ
  index.json
  <prompt-id>/
    <variant-id>.md
    <variant-id>.png
data/               # app.log, repair.log, sync_state.json, webview/ (профиль WebView2)
.backups/           # предыдущие и повреждённые версии index.json
.trash/             # удалённые промты, варианты и картинки (images/)
.conflicts/         # копии удалённых версий при конфликтах синхронизации
```

`data/`, `.backups/`, `.trash/`, `.conflicts/` лежат **вне** `prompts/`: служебные
файлы не должны уезжать на WebDAV и создавать там конфликты.

### index.json

Обязательные поля — по ТЗ, плюс необязательное `folder` у промтов внутри папок
(у промтов в корне его нет, запись остаётся ровно в формате ТЗ):

```json
[
  {
    "id": "9775efa9-0506-4942-9ad9-64d1a16d9911",
    "title": "Рефакторинг Python-модуля",
    "tags": ["код", "python"],
    "created": "2026-11-13T16:17:00.207802Z",
    "updated": "2026-11-13T16:17:00.207802Z",
    "variants": [
      {
        "id": "a6104446-0f3d-4c2c-8e6c-cb80fc64682c",
        "description": "Строгий ревьюер",
        "file": "9775efa9-.../a6104446-....md",
        "image": "9775efa9-.../a6104446-....png"
      }
    ],
    "folder": "Разработка/Код"
  }
]
```

### Файл варианта

```markdown
---
id: a6104446-0f3d-4c2c-8e6c-cb80fc64682c
prompt_id: 9775efa9-0506-4942-9ad9-64d1a16d9911
description: Строгий ревьюер
created: 2026-11-13T16:17:00.207802Z
---
Текст промта.
```

Время хранится в UTC с микросекундами и суффиксом `Z` — строки сравнимы
лексикографически, это нужно сортировке и слиянию индекса.

Папки — метаданные, а не каталоги: файлы промтов всегда лежат в
`prompts/<prompt-id>/`.

## Гарантии целостности

- **Атомарная запись.** Индекс, варианты и скачанные файлы пишутся во временный
  файл рядом, затем `flush` + `fsync` + `os.replace`. Прямой записи поверх
  `index.json` нет. Прежние версии индекса — в `.backups/` (последние 10).
- **Валидация путей.** Всё, что приходит из индекса или UI, проходит через
  `safe_path()`: запрещены абсолютные пути, `..`, разделители внутри имени,
  зарезервированные имена Windows; результат резолвится и проверяется на
  принадлежность `prompts/`.
- **Самовосстановление.** Битый `index.json` уезжает в
  `.backups/index-broken-<ts>.json`, индекс пересобирается из frontmatter
  `.md`-файлов; осиротевшие файлы подхватываются. Каждое исправление — в
  `data/repair.log` и в баннере интерфейса.
- **Чтение перед записью.** Каждая операция перечитывает индекс с диска, поэтому
  ручная правка `index.json` не затирается сохранением из UI.
- **Неразрушающие удаления.** Промт/вариант/картинка переезжают в `.trash/`,
  серверные файлы — в `_trash/` на WebDAV.

## Настройки окружения

| Переменная | Назначение |
|---|---|
| `WEBDAV_URL` | адрес каталога на WebDAV |
| `WEBDAV_USERNAME`, `WEBDAV_PASSWORD` | креды (Basic, при 401 автоматически Digest) |
| `WEBDAV_VERIFY_SSL` | `false` отключает проверку сертификата (самоподписанные) |
| `WEBDAV_TIMEOUT` | таймаут HTTP в секундах (по умолчанию 30) |
| `PROMPTMANAGER_DATA` | каталог данных (только из окружения процесса) |
| `PROMPTMANAGER_DEBUG` | `1` — devtools WebView2 и DEBUG-логи |

## Сборка

```bash
# Windows
powershell -ExecutionPolicy Bypass -File build.ps1

# macOS / Linux
bash build.sh
```

Или вручную: `python -m PyInstaller promptmanager.spec --noconfirm`.

Результат — `dist/PromptManager/` (`PromptManager.exe` на Windows). Интерфейс
копируется в `_internal/ui` и находится через `sys._MEIPASS`. Сборка под каждую
ОС делается на своей ОС: PyInstaller не кросс-компилирует. На Windows нужен
WebView2 Runtime (в Windows 11 и свежих 10 — уже есть).

**Запускать нужно только файл из `dist/PromptManager/`.** В `build/promptmanager/`
PyInstaller оставляет промежуточную копию exe без каталога `_internal` — её
запуск даёт ошибку:

```
Failed to load Python DLL ...build\promptmanager\_internal\python311.dll
LoadLibrary: The specified module could not be found.
```

Скрипты сборки удаляют эту копию, но если собирали вручную — не запускайте
файлы из `build/`, это рабочий мусор PyInstaller.

### Ошибка «Failed to load Python DLL» при запуске

Признак того, что запущен промежуточный exe из `build/`: рядом с ним нет
каталога `_internal`, где лежит `python311.dll`. Запустите
`dist\PromptManager\PromptManager.exe` (или пересоберите: `build.ps1`), либо
запускайте из исходников — `python main.py`.

## Известные ограничения

- Картинка выбирается нативным диалогом: drag&drop в WebView2 не даёт
  надёжного локального пути.
- SVG и HEIC Pillow не читает — пользователь получит понятную ошибку, а не крэш.
- CSP в `ui/index.html` содержит `script-src 'unsafe-eval'`: pywebview строит
  функции моста через `new Function`. Внешние скрипты запрещены, inline-скриптов
  нет, текст промтов выводится через `textContent`.
- WebDAV `LOCK` не используется: защита от гонок — условные PUT с `If-Match`.
- Конфликт-копии остаются локальными (`.conflicts/`) и повторно не выгружаются.
- Список не разбит на страницы: рассчитан на сотни промтов, не на десятки тысяч.
